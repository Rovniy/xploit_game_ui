# Cutting a release

A release is two files: a UPM tarball that installs into Unity, and the native
runtime zipped on its own.

## Why it is half manual

`xploit_game_ui.dll` links against the Unity Native Plugin API headers, which
belong to Unity under the Unity Companion License and are therefore not in this
repository (see [THIRD-PARTY-NOTICES](THIRD-PARTY-NOTICES.md)). A GitHub-hosted
runner has no Unity installed, so it cannot build the DLL.

The workflow splits accordingly:

- **CI verifies the tag.** `.github/workflows/release.yml` builds the whole
  engine and runs all 310 native tests on a hosted runner, checks that the tag
  matches `package.json`, and opens a **draft** release with the notes filled in.
- **You attach the binaries**, built on a machine that has Unity. One command.

If you run the workflow on a self-hosted Windows runner with Unity installed, it
builds and uploads the artifacts itself and there is nothing left to do but
publish.

## Steps

1. **Bump the version** in
   `unity/Packages/com.xploit.game_ui/package.json` and add the section to
   `unity/Packages/com.xploit.game_ui/CHANGELOG.md`. The tag and the version have
   to agree — the workflow fails if they do not.

2. **Build, test and package locally.**

   ```powershell
   .\tools\package.ps1 -Build
   ```

   That configures, builds, runs `ctest`, copies the DLL into the package, and
   writes:

   ```
   dist\com.xploit.game_ui-<version>.tgz
   dist\xploit_game_ui-native-win-x64.zip
   ```

3. **Run the Unity PlayMode tests.** CI cannot, and they are the only coverage of
   the real GPU path.

   ```powershell
   & "<Unity>\Editor\Unity.exe" -batchmode -force-d3d12 -projectPath .\unity\Sandbox `
       -runTests -testPlatform PlayMode -testResults .\build\test-results.xml -logFile .\build\editor.log
   ```

   Close the editor first — it holds the DLL open.

4. **Install the tarball into a scratch project** and open the HUD sample. A
   tarball that has never been installed is a tarball that has never been tested.

5. **Tag and push.**

   ```powershell
   git tag v<version>
   git push origin v<version>
   ```

6. **Attach the artifacts and publish** once the workflow's draft release appears:

   ```powershell
   gh release upload v<version> dist\com.xploit.game_ui-<version>.tgz dist\xploit_game_ui-native-win-x64.zip
   gh release edit v<version> --draft=false
   ```

## What goes into the tarball

`tools/package.ps1` assembles it and, in doing so, guarantees a few things worth
knowing about:

- The `.pdb` is excluded. It is around 280 MB of debug symbols and does not
  belong in a package every consumer downloads.
- Local editor state (`.idea`, `.vs`, `.vscode`) is stripped, so nothing that git
  ignores leaks into a published artifact.
- `LICENSE.md` and `Third Party Notices.md` are copied in under the names the
  Package Manager displays.
- `Third Party Licences.md` is generated by concatenating the copyright file of
  every vcpkg port that was built into this release, which is how the
  attribution requirements of Skia, ICU, FreeType and the rest are met.
- `Samples~` keeps its tilde, without which Unity would import it as ordinary
  assets.
